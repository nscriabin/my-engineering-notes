# RFCs

A Request for Comments (RFC) is a structured document used to propose, discuss, and refine architectural changes, new features, or technical designs before implementation. The process has [origins](https://en.wikipedia.org/wiki/Request_for_Comments) in the development of Internet but was widely adopted across the tech world.

When to do an RFC:

- If there is something big and important to do/fix, which can’t be achieved in the duration of a few sprints. Alternatively, when it will require a team effort for a few months.
- When you want feedback from other engineers (outside your immediate team).
- When the proposal affects multiple systems/teams.
- When you are struggling to get the proposal prioritised. Describing the proposal in a clear way to a wider audience (management is part of the audience), helps it get prioritised.
